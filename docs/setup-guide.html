02Database

Create one application role and two databases: the app database, plus a disposable one for the tests.

psql
sudo -u postgres psql <<'SQL'
CREATE USER hrms WITH PASSWORD 'choose-a-strong-password' CREATEDB;
CREATE DATABASE hrms OWNER hrms;
CREATE DATABASE hrms_test OWNER hrms;
SQL
Careful

The test suite drops and recreates the public schema of hrms_test on every run. Never point TEST_DATABASE_URL at data you want to keep.

10Authentication design

Token storageXSS exposureCSRF exposureUsed
localStorage + BearerHigh: any injected script can read and replay itNoneNo
Memory onlyMedium: lost on refresh, so it needs a refresh cookie anywayNoneNo
httpOnly cookie + CSRF double-submitLow: scripts can't read the tokenSameSite=Lax + X-CSRF-TokenYes
  1. Login verifies the Argon2id hash. It issues an HS256 JWT with sub, role, jti, ver, iat and exp, and sets the hrms_access_token (httpOnly) and hrms_csrf cookies.
  2. Axios sends cookies and echoes hrms_csrf in X-CSRF-Token on writes. Swagger and API clients use Authorization: Bearer.
  3. Every request checks the signature (HS256 only), exp, the revoked-jti list, token_version and whether the account is active.
  4. Logout deny-lists the jti. Password changes, password resets, role changes and deactivation bump token_version, which signs the user out everywhere.
  5. After 5 failed logins the account is locked for 15 minutes. Existing sessions keep working, so mistyped passwords can't end someone's session.

12Production checklist

  • ENVIRONMENT=production, a new random JWT_SECRET_KEY, and database credentials kept in a secrets manager.
  • HTTPS only with COOKIE_SECURE=true, an exact CORS_ORIGINS, and the UI and API on the same site.
  • Never run seed_demo (it refuses in production). Rotate the bootstrap admin password after first login.
  • Run alembic upgrade head as a deployment step, then start several Uvicorn workers behind a reverse proxy.
  • Rate-limit /auth/login at the proxy, schedule pg_dump backups, and purge expired revoked_tokens rows.

14Adding phases 5–8

  1. Add app/models/<module>.py with FKs to employees.id, and import it in app/models/__init__.py.
  2. Run alembic revision --autogenerate -m "<module>", review the file, then upgrade.
  3. Add the schema, the service and the router. Append the router to API_ROUTERS; main.py doesn't change.
  4. Reuse OwnEmployee for self-service and HRorAdminUser for approvals. reporting_manager_id drives manager approval chains.
  5. Add the pages, then add their sidebar entries in frontend/src/components/navigation.ts.
